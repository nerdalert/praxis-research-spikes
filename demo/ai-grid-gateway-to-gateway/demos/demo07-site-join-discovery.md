# Demo 7 — Site Join and Discovery

## Status: PARTIAL

The lifecycle state machine is proven end-to-end.  Data-plane readiness
metadata is verified.  Cross-network isolation is proven in both the
`GridSite` inventory and the routing overlay.

What is **not yet proven** in this demo:
- Automatic `GridSite` creation from SWIM discovery (harness-assisted only)
- Real mTLS certificate exchange (`publicCertPem` remains `null`)
- Automatic `Pending → Discovered` transition without a kubectl patch
- Data-plane routing through the consumer gateway (proven separately in Demos 1–4)

## What This Proves

| Proof Point | Evidence |
|---|---|
| Lifecycle type system exists | `GridSitePhase` enum: Pending, Discovered, Connecting, Active, Unreachable, Left |
| Operator preserves Pending | Harness creates site; controller reconciles; phase remains Pending |
| Operator preserves Discovered | Harness patches to Discovered; next reconcile leaves it Discovered |
| Operator preserves Connecting | Harness patches to Connecting; next reconcile leaves it Connecting |
| Operator preserves Active | Harness patches to Active; next reconcile leaves it Active |
| Joining site has routing data | `spec.egress.address` + `spec.gridNetworkRef` + `metadata.name` verified |
| GridSite inventory isolation | Wrong-network site absent from correct-network site list |
| Overlay cross-network isolation | Wrong-network `InferenceProvider` absent from correct-network overlay |
| Primary model in overlay | `model-sjd-primary` → `site: op-e2e-sjd-primary` confirmed |
| Joining model in overlay | `model-sjd-joining` → `site: op-e2e-sjd-joining` confirmed |

## Architecture Flow

```
East cluster (primary / kind-grid-site-east)
  ├─ operator (SWIM primary, no seeds, GRID_SWIM_SITE_NAME=site-east)
  ├─ GridNetwork/op-e2e-sjd-net (gatewayRefs: [op-e2e-sjd-gw, localSiteName: site-east])
  ├─ GridNetwork/op-e2e-sjd-wrong-net (no gatewayRefs — isolation target)
  ├─ GridSite/op-e2e-sjd-primary (network: sjd-net, egress: 172.18.0.4:8443, label: primary)
  ├─ GridSite/op-e2e-sjd-joining (network: sjd-net, egress: 172.18.0.5:8443, label: joining)
  ├─ GridSite/op-e2e-sjd-wrong (network: sjd-wrong-net — cross-network isolation)
  ├─ InferenceProvider/op-e2e-sjd-prov (sjd-net, siteSelector: sjd-site=primary)
  ├─ InferenceProvider/op-e2e-sjd-prov-joining (sjd-net, siteSelector: sjd-site=joining)
  ├─ InferenceProvider/op-e2e-sjd-prov-wrong (sjd-wrong-net — must not appear in sjd-net overlay)
  └─ ConfigMap/grid-overlay-op-e2e-sjd-net-op-e2e-sjd-gw (generated by operator)

West cluster (joining / kind-grid-site-west)
  └─ operator (SWIM peer, seed=east bind addr, GRID_SWIM_SITE_NAME=site-west)
     (no fixtures applied — west only provides a second SWIM member for membership proof)

SWIM gossip:
  site-east ←→ site-west (UDP, 127.0.0.1:{dynamic ports}, loopback)
```

## Lifecycle State Table

| Phase | Meaning | How Triggered in Demo 7 | Phase 2 (production) |
|---|---|---|---|
| `Pending` | Site record created, not yet seen via SWIM | Kubernetes apply (created by harness) | Kubernetes apply or CRD controller |
| `Discovered` | SWIM has seen this peer | Harness kubectl patch | SWIM membership event → controller |
| `Connecting` | mTLS certificate exchange in progress | Harness kubectl patch | mTLS handshake initiation → controller |
| `Active` | SWIM + mTLS + capability + data-plane ping | Harness kubectl patch | All four conditions confirmed → controller |
| `Unreachable` | Previously active, probes failing | Not exercised | SWIM probe failure → controller |
| `Left` | Graceful departure or hard timeout | Not exercised | SWIM leave event or timeout → controller |

The controller's `determine_phase()` in Phase 1 returns the current phase
unchanged.  Each harness patch is preserved through the next reconcile —
this is what the test measures.  The controller is not broken; it is
intentionally deferring automatic transitions to Phase 2.

## Limitations

| Limitation | Status |
|---|---|
| `GridSite` creation is automatic | **No** — harness applies GridSite objects via kubectl apply. In production, Phase 2 will create them automatically from SWIM membership. |
| Lifecycle transitions are automatic | **No** — harness patches `status.phase` via kubectl. Phase 2 will drive transitions from SWIM events and mTLS handshake. |
| mTLS certificate exchange is real | **No** — `status.publicCertPem` is null; no cert material is exchanged. Certs are generated locally by the operator's `certs` crate but the exchange protocol is Phase 2. |
| `connectedSites` in GridNetwork reflects two-node SWIM | **Partial** — east GridNetwork shows `connectedSites=1` because the west operator is in a separate k8s context. SWIM two-node convergence is proven separately in `verify-swim-membership`. |
| Data-plane routing through consumer gateway | **Not proven here** — Demos 1–4 prove E2E routing. Demo 7 proves lifecycle and routing metadata only. |
| Per-request dynamic scoring rebalancing | **Not proven** — overlay is static for the duration of the test. |
| Automatic `GridSite` creation from SWIM member records | **Not proven** — this is the key missing piece for a fully automatic Phase 2 join flow. |
