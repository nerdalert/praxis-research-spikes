## What This Proves

1. **Terminal request-phase orchestrator**: Praxis owns the model/tool loop without using the normal upstream proxy path or `on_response_body` hooks.
2. **Non-streaming loop**: model → function_call → tool execution → function_call_output → model → final response.
3. **Request-scoped tool authorization**: tools must be both advertised in the request AND configured in Praxis config. Unadvertised tools are rejected.
4. **Buffered SSE streaming**: function_call arguments split across SSE delta events are assembled before tool execution.
5. **State persistence**: `store:true` persists the full conversation transcript; `previous_response_id` replays it before new input.
6. **Fail-closed behavior**: missing previous response returns 404 without backend calls; unadvertised tools return 400 without tool calls.
